# Sensor pipeline and MQTT architecture

The simulator generates temperature at 1 Hz around 4 degrees Celsius with standard deviation 0.3, vibration RMS at 0.5 Hz around 0.45 g with standard deviation 0.05, and timestamped door transitions. Temperature drift adds 0.08 degrees per reading. The vibration fault changes its distribution to mean 1.2 g and standard deviation 0.15. Combined mode activates both. Explicit seeds and unique run identifiers make captures reproducible without mixing independent runs. We retain manifests, acknowledged counts and raw JSONL files.

The topic prefix is logibridge/trucks/TRUCK_001. Temperature, vibration_rms and door_event feed inference; inference and alerts carry its local outputs. All use QoS 1 with non-retained messages. QoS 1 permits redelivery, so message identifiers and database uniqueness checks handle duplicates. The consumer acknowledges after processing and committing events. Retaining old incident messages would risk confusing a fresh run with a historical condition. Heartbeats travel through the HTTP outbox to the operations service rather than an additional sensor topic.

Both numerical streams use five-sample trailing averages. Filtering uses only current and past readings and discards incomplete warm-up. Each full 30-second window contains 30 temperature and 15 vibration readings, and windows advance every ten seconds. Full filtering support makes the first usable window approximately 10-40 seconds after start. Missing or out-of-order readings cause explicit rejection rather than invented replacement values. This collection delay is separate from model invocation latency. Five samples span four seconds of temperature history but eight seconds of vibration history. We therefore align complete filtered windows rather than equating sample counts across streams. A new run resets filter state, preventing the preceding experiment from supplying a fresh experiment's warm-up.

Feature-level fusion concatenates temperature mean, population standard deviation and fitted rate of change with vibration RMS, absolute peak and Fisher excess kurtosis. The slope uses actual sample timestamps and converts seconds to minutes. Constant vibration receives a documented finite kurtosis sentinel. Door state remains contextual information. Labels and anomaly names never enter the numerical vector. Raw data-level concatenation would require unnecessary alignment of asynchronous event and numerical streams. Decision-level fusion would need separate models and rules to reconcile their outputs. Six physically interpretable features provide one compact model interface while preserving sensor-specific preprocessing.

An independent ten-minute clean run with seed 1001 produced 57 complete feature windows. We computed and froze six means and standard deviations in training_stats.npy, with feature-order metadata and a SHA256 identity. Runtime loads and transforms only. It never fits statistics on incoming anomalies. The required three-sigma experiment shifted the saved means by three original standard deviations and retained the original standard deviations. Correct and shifted statistics both yielded 100% M1 validation accuracy, a measured change of zero percentage points. This result does not establish that incorrect preprocessing is generally harmless; the synthetic classes remain strongly separated. Shared feature code and recipe metadata reduce training-serving skew. Tests check duplicates, warm-up, exact feature ordering, closed-window causality and missing support. Dataset construction validates normalisation provenance before training, making an accidental change observable instead of silently producing incompatible inputs.

Operational severity combines the latest model class with independent raw-temperature limits around the assignment's 4 degree setpoint. Deviations greater than one degree trigger Warning and greater than three trigger Critical. The model may still be warming up when a physical alarm occurs. SQLite stores local events and an outbox. The backend confirms matching event identifiers before deletion from the pending queue, enabling retries without duplicate logical incidents. The completed post-deployment run acknowledged 71 sensor messages, produced a fresh Normal prediction and left zero pending uploads; local acknowledgements and remote unique events both reached 72.

Broker health uses `logibridge/system/broker_health`. Alerts and heartbeats also enter the local SQLite outbox for HTTP acknowledgement by operations; heartbeats are not a separate sensor MQTT leaf. Numerical values are feature-level fused. Door context and simulator anomaly metadata do not enter the model vector.
